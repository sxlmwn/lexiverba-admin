## 1. Context

I'm building **LexiVerba**, a certified-translation platform with multiple role-based portals (customer, agency, QA, translator, notary, courier, referral partner, and admin). Five of these portals already exist as working React codebases with an established, consistent design system. I need you to build the **6th portal: the Admin Portal** — the top-level "Super Admin Control Center" that oversees the entire platform.

I'm attaching the zips of the 5 existing portals as reference. **Study their shared design system carefully and replicate it exactly** — do not introduce a new visual style. I'm also attaching a screenshot of an early draft of the admin dashboard — use it only for **layout and content ideas** (what sections/stats/cards exist), not for its dark-only look; the final admin portal must support both light and dark themes like the others.

## 2. Tech stack

- React + TypeScript + Vite
- Tailwind CSS (v4 style, `@import "tailwindcss"` + `@custom-variant dark`)
- **shadcn/ui** full component set (Table, Dialog, DropdownMenu, Tabs, Select, Badge, Card, Sheet, Command, etc.) — the admin portal is the most data-heavy portal of all (user lists, agency lists, invoice tables, logs), so use shadcn's Table/Dialog/DropdownMenu components rather than hand-rolled markup, the same way the QA, Notary, and Courier portals do
- Material Symbols Outlined for icons (`font-variation-settings: 'FILL' 0, 'wght' 600, 'GRAD' 0, 'opsz' 24`)
- Inter font throughout
- No backend — frontend-only with realistic **dummy/mock data** hardcoded in the components (no Supabase, no real API calls), exactly like all 5 existing portals

## 3. Design system — match this exactly

**Colors (CSS variables, light / dark):**
```css
:root {
  --c-bg: #f8fafc;
  --c-surface: #ffffff;
  --c-accent: #2563eb;
  --c-accent-hover: #1d4ed8;
  --c-text: #0f172a;
  --c-text-muted: #64748b;
  --c-border: #e2e8f0;
  --c-success: #10b981;
  --c-warning: #f59e0b;
  --c-danger: #ef4444;
  --c-info: #3b82f6;
}
.dark {
  --c-bg: #09090b;
  --c-surface: #18181b;
  --c-accent: #3b82f6;
  --c-accent-hover: #2563eb;
  --c-text: #fafafa;
  --c-text-muted: #a1a1aa;
  --c-border: #27272a;
}
```
Dark mode base is a true neutral charcoal/near-black (`#09090b` bg, `#18181b` surfaces / sidebar `#121215`), **not** navy or slate-tinted black.

**Cards & shape:**
- Large rounded corners: `rounded-[2.5rem]` on stat/metric cards, `rounded-2xl`/`rounded-3xl` on smaller cards, list items, dropdowns
- `smooth-card` treatment: `backface-visibility: hidden`, `transform: translateZ(0)`, `background-clip: padding-box` (prevents corner rendering artifacts)
- Soft floating shadows: light mode `0 16px 40px -10px rgba(0,74,198,0.08), 0 6px 16px -2px rgba(0,0,0,0.04)`; dark mode much deeper `0 20px 50px -12px rgba(0,0,0,0.8)...`
- `float-hover`: cards lift `translateY(-6px)` on hover with a blue-tinted shadow and a blue border glow — used on all clickable stat/metric cards
- Metric/stat cards invert to a **blue gradient fill on hover** (`from-blue-600 via-blue-700 to-blue-900`, white text, large faint icon bleeding off the top-right corner) instead of just a border change — this is the signature "wow" interaction from the existing portals, replicate it on the admin stat cards too
- Badges use color-specific glow shadows (`badge-glow-emerald`, `badge-glow-amber`, `badge-glow-rose`, `badge-glow-purple`) that lift and brighten on hover

**Typography:**
- Inter, antialiased
- Big numbers (stat card values): `text-3xl lg:text-4xl font-semibold tracking-tight`
- Section eyebrow labels: `text-[10px] font-semibold uppercase tracking-[0.2em]` or `tracking-widest`, muted color
- Body/labels default to small, dense text (`text-xs`, `text-[10px]`, `text-[11px]`) — this is a dense, information-rich professional UI, not a spacious consumer app

**Motion:**
- Page entrance: fade + slide up (`pageEnter` keyframe, translateY(10px) → 0, opacity 0 → 1)
- All hover/transition timings 0.2s–0.35s, `cubic-bezier(0.22, 1, 0.36, 1)` for the nicer "rise" hover on list rows

- Don't make it a glassy/frosted/neon look — it should look like clean, dense, professional office software.
- Don't wire up any real backend/Supabase calls — mock data objects/arrays only, like the other 5 portals.
- Don't drop any sidebar item — the full list in Section 4 must all be present and clickable, even where the page behind it is a placeholder.
